# 02 · 使用说明（部署 / 维护 / 调试）

> 面向使用者/维护者的操作手册。用自然语言讲清「怎么装、怎么用、数据怎么维护、出问题怎么自查」。
> 技术选型见 [`01-技术栈说明.md`](01-技术栈说明.md)；代码在哪、怎么连见 [`../ARCHITECTURE.md`](../ARCHITECTURE.md)。

## 0. 一分钟速览

| 你要做的事 | 命令 / 入口 |
|---|---|
| 首次安装前端依赖 | `sh manager.sh setup` |
| 开发（Vite + Rust，热更新） | `sh manager.sh dev` |
| 只预览前端界面（无 IPC） | `sh manager.sh web` |
| 跑测试 | `sh manager.sh test` |
| 交付前检查（fmt / clippy / tsc） | `sh manager.sh check` |
| 生产打包 | `sh manager.sh package` |
| 统一管理脚本全部命令 | `sh manager.sh help` |

# 一、部署

## 1. 前置条件

- Rust stable + Cargo（`cargo fmt` / `cargo clippy` 组件）。
- Node.js 20.19+ 或 22.12+ 与 npm。
- 平台依赖：Windows 的 MSVC Build Tools 与 WebView2 Runtime；macOS 的 Xcode CLT；Linux 的 WebKitGTK 4.1 等（见 [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/)）。

## 2. 开发与打包

```bash
sh manager.sh setup     # npm ci
sh manager.sh dev       # tauri dev：Vite + Rust
sh manager.sh test      # tsc + node:test + cargo test
sh manager.sh package   # tauri build，安装包复制到 dist/
```

- `package` 首次会下载 Rust 依赖并编译，通常要几分钟到十几分钟；之后的增量构建会快很多。
- 安装包原始位置：`src-tauri/target/release/bundle/`；`package` 会把 `*.msi / *.exe / *.dmg / *.deb / *.rpm / *.AppImage`（和 macOS 的 `*.app`）复制到 `dist/`。
- `sh manager.sh build` 只构建前端，不生成安装包。

# 二、维护

## 3. 版本号怎么发

1. 只改 `src-tauri/Cargo.toml` 的 `version`（`tauri.conf.json` 不写 `version`）。
2. 在 `CHANGELOG.md` 把 `[未发布]` 归档到新版本号下。
3. `sh manager.sh test && sh manager.sh package`。

## 4. 图标怎么换

`src-tauri/icons/` 里是占位图标。准备一张 1024×1024 的 PNG，然后：

```bash
npm run tauri icon path/to/icon.png
```

命令会重写 `src-tauri/icons/`（含 `.ico` / `.icns` 与各尺寸 PNG）。不要手改文件名或尺寸；`tauri.conf.json` 的 `bundle.icon` 已指向标准文件名。

## 5. 用户数据与日志

- 用户数据 / 缓存用 Tauri 的 `app_data_dir()` 定位，不要写程序安装目录。
- 开发日志直接看 `tauri dev` 终端；生产日志如需落盘，接 `tauri-plugin-log` 并写入 `app_log_dir()`。
- 卸载时是否保留用户数据由安装器决定；涉及用户数据的功能要写清保留策略。

## 6. 依赖锁定

- `package-lock.json` 入库，脚本里用 `npm ci`。
- `src-tauri/Cargo.lock` 在首次构建时生成，**应提交入库**，保证可复现构建。
- 升级 Tauri / Rust 依赖后跑 `sh manager.sh check && sh manager.sh test`，再实测窗口与 IPC。

# 三、调试

## 7. 出问题怎么自查

1. 先看 `tauri dev` 终端：Rust 编译错误、Vite 端口冲突、窗口加载失败都会打印在这里。
2. 前端报错：开发模式右键 / `F12` 打开 WebView DevTools，看 Console 与 Network。
3. IPC 报错：确认命令在 `commands.rs` 定义、在 `lib.rs` 的 `generate_handler!` 注册、在 `src/api.ts` 用同一个名字 `invoke`；`npm test` 会校验这三方一致。
4. 浏览器预览里 IPC 报「未检测到 Tauri 运行时」是正常的：`sh manager.sh web` 只启动 Vite，没有 Rust 进程。

## 8. 常见问题（FAQ）

- **端口 1420 被占用**：Vite 设了 `strictPort`，会直接失败而不是换端口。改 `tauri.conf.json` 的 `build.devUrl` 即可，`vite.config.ts` 会自动跟随。
- **Windows 上窗口空白 / 加载失败**：确认 WebView2 Runtime 已安装；开发模式检查 Vite 是否已就绪（`devUrl` 能否在浏览器打开）。
- **Linux 编译报缺库**：按 Tauri prerequisites 安装 `webkit2gtk-4.1`、`libgtk-3`、`libayatana-appindicator3` 等系统包。
- **首次打包很慢**：Rust release 全量编译属正常；后续增量会明显加快。

## 9. 怎么跑测试

`sh manager.sh test` 依次跑：

1. `tsc --noEmit`：前端类型检查。
2. `node --test`：`tests/contract.test.mjs` 校验 identifier / CSP / capabilities / 构建链路 / IPC 三方一致。
3. `cargo test`：Rust 侧单元测试与编译检查。

三项都跑完再汇总，某一项失败不会让其余项「没跑却显示通过」。
